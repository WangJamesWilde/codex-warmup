# Codex 预热与续聊 v0.6.0（原生侧边栏插件）

> 实验性停更源码快照，非 OpenAI 官方产品；不保证后续版本、模型或额度规则的兼容性。公开版安装与许可说明见[仓库首页](../README.md)。

本版提供原生导航中的“预热管理”页面、常驻预热，以及用户明确选定的续聊规则。新安装/升级不自行添加对话；不修改已有对话的模型、推理档位或权限。

## 已实现

- 通过官方 `codex app-server` 读取账号及额度，不直接读写/复制凭据文件。
- 每60秒检查真实五小时/周额度，无模型推理的定时轮询；有明确的新窗口且额度可用时才发送。
- 预热固定 `gpt-5.6-luna` / `low`，通过 Deck 式 `codex exec` 新建独立的 ephemeral 会话，忽略用户配置/规则、空工作区、只读沙箱和短指令。其他对话设置不受影响。它不是禁止一切读取/工具的隔离容器。
- 原子占位防重复，失败/超时不自动重试同一周期；请求完成不冒充已证明服务端窗口开启。
- 登录账号变化即暂停；缺CLI、失去登录或配额未知时等待，不登录、不安装、不切API、不购买额度、不使用重置券。
- 后台无需Codex主窗口；可选Windows登录自启，不唤醒睡眠电脑。重启/睡眠后重新读取服务器，不能仅凭本地时钟发送。
- 插件服务完成MCP握手时，检查并恢复原先已启用但确认退出的后台。不重新启用主动暂停的后台，不改变账号绑定、额度快照、规则或发送账本。多个聊天同时加载时用SQLite原子占位，只启动一个后台。
- 自动把已有的系统 HTTP/HTTPS 代理传给预热子进程，不修改全局代理；如果代理软件未运行，会等待连接恢复，不自行启动其他软件。
- 十一个MCP工具：管理页、状态、只读刷新、启用、暂停、搜索对话、保存规则、快捷开关、执行次数、移除规则、低额度提醒配置。也提供直接管理命令。
- 官方 MCP Extensions 全局入口，内置自包含白色管理页面，无系统托盘、外置窗口或常驻网页服务；页面操作不需要模型判断。
- 自定义续聊消息默认下一次额度恢复后尝试一次，可逐条设置重复。即使别的对话已经启动窗口，续聊仍独立检查。投递前复核账号、额度和对话状态，并保留防重复账本。
- 顶部“快速续聊”最近对话列表支持一键加入/取消；首次默认“继续／单次”，取消保留配置，再次加入保留消息、执行方式及未用完的次数。

## 前提与安装

Windows 10/11；Python 3.10+；已有、可使用的 Codex CLI 与 ChatGPT 登录。目前只支持服务器明确返回300分钟主窗口和有效周窗口的账号。另一个Windows电脑尚未测试。

原生管理入口要求支持 MCP Extensions 的桌面客户端；官方参考最低版本为26.928.20710，本机26.1023.6123.0已由用户确认入口和页面正常。另一个Windows电脑尚未做迁移实测。

在项目的上一级执行 `install.ps1`，它按官方CLI流程注册本地市场并安装插件。`-Enable` 明确允许在符合条件时消耗订阅额度；`-LoginStart` 明确注册当前用户的登录启动项。不会上传账户/插件到云端。

安装文件位置可变；脚本根据实际路径登记。后台状态通过 `CODEX_WARMUP_HOME` 或 `HKCU\Software\CodexWarmup\DataDir` 定位。没有指定时小型状态文件回退到 `%LOCALAPPDATA%\CodexWarmup`。公开版安装器、管理页和后台使用同一套默认定位规则；不要公开或随发布包复制状态数据。

插件缓存是官方安装流程写入的 `~/.codex/plugins/cache`，代码很小；CLI本身仍可能在原用户目录维护自己的日志/登录状态。插件不承诺零C盘写入。

## 使用

1. 打开 Codex 左侧导航或“更多”中的“预热管理”。升级后如仍显示旧页面，关闭管理页并重新从入口打开，不需要重启正在工作的 Codex。
2. 快速加入：在最近对话列表点“加入续聊”，再点“已加入”即可取消。不立即发送，也不删除自定义配置。没有找到的对话可以搜索或加载更多。
3. 详细配置：点击“添加规则”，选择对话并填写消息，直接保存即启用，不需要额外勾选授权/启用/重复框。原规则存在时保存会更新它，不创建重复规则。
4. 规则右上角是滑动开关；底部“编辑”和“移除”之间可选择“单次”“每次额度恢复后重复”“指定次数”。指定次数填写1到1000的整数，按Enter或移开焦点保存。次数用完自动停用；取消再启用保留剩余次数，用完后主动重新启用则恢复所设次数。
5. “编辑”只需修改消息再保存；执行方式与未用完次数会保留。切换执行方式或改变次数会重新设置相应计数，从下一次恢复生效。“移除”不删除对话或发送账本。
6. 顶部“暂停后台”同时暂停预热和续聊。取消开关只阻止尚未投递的消息，不撤回已经排队的消息，也不中断原对话。

所有保存/加入操作只登记下一次恢复后的发送意图。次数是投递尝试次数，结果不明时计一次、不自动重发；它不是账号重置次数，不会调用重置券接口。旧版规则自动迁移，原消息与单次/重复设置保留。

### 预输入与额度中断恢复

管理页新建/首次快捷加入默认选择“额度恢复后发送预输入（正常收尾也可）”。编辑时可以改为“仅续接因额度不足中断的任务”。两者都必须有服务器确认的**下一次额度恢复**，不是按本地时间盲发；窗口已被其他对话启动也能独立检查。

- `after_recovery`：用户明确安排了下一次的消息。正常完成或真实额度中断均可，不要求故意撞额度上限。单次绑定保存时选中的回合；之后有新的手动工作则不复活旧计划，需重新编辑保存。若对话在恢复后仍继续工作并完成，也不重复启动。
- `quota_stop`：保持旧版的严格额度中断恢复，只接受最后一轮带明确`usageLimitExceeded`及完成时间的证据。升级不改变旧规则的条件；API调用省略`trigger`时保留旧条件，新API规则省略仍使用`quota_stop`。
- 重复/指定次数的显式预输入，是用户允许每次恢复后检查当时的空闲对话，不绑定最初的回合。同一次恢复最多投递一次，同一原生回合仍不重复投递。次数用完即停用。

运行中、已知等待用户输入/审批、归档、人工暂停、未知错误、普通429或目标预算受限都不投递。不能仅靠模型普通文本里的问句准确判断“正在等用户”，模型需要用户决定时应取消对应预输入，而不是把提示当作代答许可。显式预输入也不是对未选定闲置对话的任意定时发消息工具。

新增独立的意图/周期占位表，保留原规则、消息、次数和发送账本，不把正常完成伪装成额度失败。

### 低额度提醒（可选，默认关闭）

管理页可选剩余5%或3%时提醒。插件打包官方`PostToolUse` Hook：工具返回后，在当前回合的安全点附加一段简短额度提示，不另开聊天，不调用模型判断，不排队下一回合，不中断、批准或改写原工具。模型按已有任务授权决定是否保存预输入，Hook本身不创建规则。

提醒随后台总开关暂停；后台需要持续提供新鲜快照。仅开启提醒配置但后台暂停时不会提示。

安装并不自动信任Hook。请按Codex的审阅提示检查来源与脚本后信任；CLI可用`/hooks`检查本插件。插件不会修改信任记录、冒充管理员Hook或使用绕过开关。管理页开启仅保存提醒配置，不能代替宿主信任；未信任时提醒不会执行。

脚本只读取本插件已有SQLite里的开关、账号绑定及最新额度快照；不联网、不读账号凭据、不读取或记录工具正文/会话全文。只在有效、同账号、尚未过期的五小时快照且余量大于0时提示；每周期每主对话原子占位一次。已知子代理事件不消耗主对话提示次数。异常、数据库忙、过大输入等均静默放过原工具；最近30天的提示占位保留在插件状态目录。

它是尽力提醒，不保证在长时间纯推理、长工具或额度突然耗尽之前送达；扫描快照约60秒更新，过期数据不提示。附加到模型上下文的简短提示仍可能消耗少量输入tokens，并非零成本。真实宿主在用户信任后如何展示与投递仍需验收，隔离脚本测试不能代替它。

Codex桌面程序退出时，续聊等待，不会自动打开程序；后台预热仍可独立运行。单次规则尝试投递后即停用，包括结果不明的情况；同一个额度中断轮次不重复投递。“已排队”不等于模型已经开始运行或完成，真实执行结果应在原对话查看。

在Codex说“查看预热状态”或“暂停预热”即可使用插件工具。若当前对话尚未发现新插件，先使用以下直接命令，不必为刷新工具创建新聊天。

```powershell
python -B server.py status
python -B server.py pause
python -B server.py enable
python -B server.py autostart-off
```

`enable` 会验证当前账号并启动后台，属于消耗额度的授权动作。不要让另一个AI未经你同意调用。`verify-send` 是会消耗额度的一次人工验证，不是状态查询，同账号已执行过则拒绝再次运行。

### Aion 协作恢复适配（已通过隔离联调）

本版包含可选的 Aion 恢复适配器；未配置时保持原版普通续聊行为。已使用真实桥代码、独立SQLite和模拟模型通过联调，并对运行中的真实CLI做仅查询不存在回执的只读检查。安装接入不等于真实协作已经自动恢复，完整链路仍需在后续自然额度恢复时观察。

在桥端提供可信的 `recovery-cli.mjs` 后，使用本机实际路径一次配置：

```powershell
python -B server.py bridge-config --bridge-cli "<桥项目的绝对路径>\recovery-cli.mjs" --node-path "<Node的绝对路径>\node.exe"
```

只保存可迁移后重新设置的程序路径，不复制桥的令牌、群上下文文件或账号凭据；配置本身不发消息。省略 `--node-path` 时从 PATH 发现 Node。迁移电脑后需重新配置本机路径。

配置后，每次符合续聊条件时先按原生对话 ID 和失败回合 ID 只读查询桥：明确普通对话才沿用 `codex queue`；唯一匹配协作时由桥恢复原请求关联并投递一次。桥不可达、归属不明、任务结束或过期时不回退普通“继续”，也不消耗尚未进入投递阶段的规则次数。常驻 Luna 预热不依赖桥。

正常完成的显式预输入另用协议1的只读`resolve_preinput(threadId,completedTurnId)`，校验两个ID回显；只接受`ordinary/blocked/ambiguous`。它不产生恢复句柄，不改Aion讨论、投递或唤醒预算，不赋予群共享权限。桥不支持新分类时不发、不扣次数，不绕过原边界；额度失败分支仍沿用原`resolve/resume/status`契约。

协作投递前持久化尝试 ID；发送结果未知时仍消耗一次尝试，之后仅查询原尝试回执，绝不换 ID 重发。后台重启也保留这项约束。v0.5.1不再于24小时后自动停止回执跟踪；后台开启且账号、桥配置一致时，每60秒最多查询一次，收到终态后停止。持续查询不代表重新发送或增加任何规则的次数。`accepted` 仅代表桥已受理；`queued` 必须带原生队列回执；确认原生回合 ID 后才标记已开始/完成，回合完成不等于整个任务通过验收。

Aion讨论的有效期与唤醒策略由所接入的桥端负责；预热端不另设24小时回执截止，也不自行增加桥端预算或扩展授权。手动暂停、结束、撤回、成员移除仍有效，历史过期或结束任务不自动复活。单次、重复及指定次数继续按用户保存的规则执行。

可选跨项目测试：将 `CODEX_WARMUP_BRIDGE_SOURCE` 设为本机桥源码目录，然后运行 `python -B -m unittest test_bridge_integration -v`。测试使用真实恢复CLI/网关和临时回环服务，但只创建项目内的独立夹具数据与模拟模型，不连接运行中的真实桥、不发真实模型请求；临时服务和夹具在结束时关闭/清理。兼容旧版三小时冻结倒计时与新版无限期策略；后者模拟等待48小时。也覆盖丢失受理回复、仅一次投递、重启后查回执及完成消息返回同一测试群。

### 暂停、卸载与恢复

1. 先执行 `pause`，后台当前操作结束后退出，不会中断桌面端其他任务。
2. 执行 `autostart-off` 移除本插件唯一的登录启动项 `HKCU\...\Run\CodexWarmup`。
3. 需要卸载时执行 `codex plugin remove codex-warmup@codex-warmup-local`。卸载插件本身不会替代第1、2步。

保留状态账本以防重复发送。不要为了重试删除数据库；如需完整清理，先确认后台已停止，再由用户明确授权删除这个插件专用数据目录。没有修改系统级启动项或其他软件的登录自启。

## 验证和限制

v0.5.2修复在额度恢复后重新启用后台会丢失恢复事件的问题：替换额度快照前先保存同账号的真实恢复证据。无旧证据、账号变化、人工暂停、正在运行和已处理回合仍不会凭空恢复；不会补发用户已手动续上的对话。

v0.5.3补上插件重新加载后的后台恢复。它不调用`enable`，不会覆盖重置前的额度证据；正常检查仍复核账号和最新中断回合，已手动续上的对话不补发。旧进程被确认终止后，只回收与其启动记录相匹配的运行权，不必等四分钟旧租约到期。若进程仍存活但心跳过期，或系统无法确认进程状态，则只显示异常，不杀进程、不另起重复后台。加载期间的启动失败记录安全摘要，不阻断管理页或工具发现。

这不是阻止Windows更新终止进程，也没有新增系统守护服务、计划任务或持续的外部监控。自动恢复发生在下次插件MCP服务握手完成时；仅关闭并重开一个仍复用旧连接的管理页不保证产生重载。Codex关闭后如果独立后台又被外部终止，则等待下次插件加载或原有Windows登录自启。状态和刷新工具本身仍只查询，不是强制重启按钮。

管理页顶部按实际健康状态显示“运行中／正在启动／后台已退出／后台无响应／状态待确认／已暂停”，不再把配置开关打开当作运行正常。“后台诊断”区分开关暂停、进程不存在与心跳过期，并显示最近异常阶段、元数据RPC方法和正常/异常退出原因。每条已启用规则可显示未发送原因。历史异常不会被当作当前后台状态；进程被强制结束时无法自行写退出记录，页面会如实显示进程已退出而不猜测具体原因。状态查询本身不会重新启用后台。

诊断仅保存在插件数据目录：SQLite保存最近启动/退出/异常摘要，`diagnostics.jsonl`最多保留约3×256KiB的滚动日志。只记录阶段、异常类型、错误代码和进程编号，不写入原始异常正文、密码、令牌、用户消息或对话正文。登录自启命令、规则及投递账本不因诊断迁移或清空。

离线测试：`python -B -m unittest -v`。覆盖重复发送、8线程竞争、账号变化、周限额阻塞、额外恢复、模型不可用后的待发送保留、暂停和MCP握手/工具调用。

后台恢复测试还使用独立数据目录中的真实Windows测试进程：结束该进程后重新走MCP握手，验证自动恢复且重复加载不再起第二个；夹具明确替换额度检查函数，不连接Codex、模型或真实Aion。该测试不等同于再次执行Windows商店更新，也不代表已实测下一次自然额度恢复。

开发环境验证（2026-10-30，Codex CLI 0.165.0-alpha.1.2 / Python 3.13.1）：Luna low 授权短请求已完成且未观察到工具调用；原生侧边栏入口及页面由使用者确认可用。指定测试对话的一条授权短消息曾成功投递并获得回复，未观察到工具调用。该验证没有创建常驻续聊规则，不代表其他版本或环境的兼容性。

本地单元测试及浏览器离线宿主模拟覆盖规则授权、默认单次、重复、防重、后台暂停、账号变化、额度恢复后窗口已被其他任务使用、人工暂停/审批保护，以及1440/768/375宽度布局。模拟宿主不代表完整桌面端端到端测试；自然额度恢复后自动投递仍待观察。登录自启注册已检查，未重启电脑做实测。

真实的空闲新窗口是否被服务器计入，只能在后续自然重置时观察，不能用一次回复hi作证明。预热只改变使用时机，不增加周额度。关闭工具/短指令可以减小输入，但并不等于零tokens或绝对最低开销。

## 前端构建

正常使用无需Node.js、前端依赖或网页服务器；插件包含已构建的自包含HTML及第三方许可证。仅修改前端时，在上级 `ui-build` 安装锁定依赖后执行 `node build.mjs`，再按现有市场流程升级插件。依赖目录在插件之外，不进入官方插件缓存。可用 `node build.mjs --qa` 构建纯模拟测试页面；临时 `serve-qa.py` 仅监听127.0.0.1，只服务这一个模拟页面，不提供真实工具接口，并会自动退出。
