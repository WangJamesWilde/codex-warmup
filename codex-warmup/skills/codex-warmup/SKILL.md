# Codex 预热

优先使用本插件 warmup_status / warmup_refresh / warmup_enable / warmup_pause 工具。

- 状态工具和刷新工具本身不触发模型推理。不要通过发 hi 测状态。
- 启用前须有用户明确授权消耗订阅额度；随后调用 warmup_enable(confirm_quota_spend=true)。
- 模型固定为 gpt-5.6-luna，推理 low，仅限预热新会话，不修改其他会话。
- 不读取/复制 auth.json，不要求 Cookie/API Key，不购买额度，不兑换重置券。
- 后台每60秒读取官方元数据，观察可用的五小时/周额度；不按本地时钟盲发。
- 同一周期发送前原子占位，失败/超时结果不明不重试。
- UI 不必打开；若 CLI 不存在、登录失效或配额未知，等待并记录原因。
- 插件MCP握手完成后会检查原先已启用的后台：仅在确认旧进程不存在（或尚未启动）且运行权可安全接替时拉起；不会调用enable、更换账号绑定、覆盖额度证据或修改规则。用户主动暂停时不自动恢复。多个聊天同时加载不会重复启动；存活但无响应、进程状态不明时不擅自杀进程或另起后台。
- 自动恢复依赖插件服务再次加载，不是独立系统守护服务；Codex关闭后若后台又被外部终止，等待下次加载插件或原有Windows登录自启。顶部按真实诊断显示运行中、正在启动、后台已退出或状态待确认，开关启用不代表进程在运行。
- 暂停用 warmup_pause；移除登录自启需按用户请求执行 server.py autostart-off。
- 入口是 Codex 左侧导航/更多中的“预热管理”，不是浏览器标签、独立窗口或系统托盘。用户点击后直接调用本地工具，不需要模型推理。
- warmup_chats 只读搜索对话；warmup_rule_save 仅在用户明确选定对话和消息后保存（confirm_send=true）。不得自行选择对话、默认加入当前任务或复制用户隐私内容。保存不会立即发送，规则从下一次额度恢复起生效。
- 每条规则默认单次，可选每次恢复后重复或指定次数（1到1000，指投递尝试次数，不是账号重置券）。用户明确说“预输入／下一次恢复后发送”时，用warmup_rule_save指定trigger=after_recovery：保存时锁定所选回合，正常完成或明确额度中断均可；单次保存后有新的手动回合、恢复后仍继续工作的回合不投递。用户只允许恢复额度中断任务时用trigger=quota_stop，仅认usageLimitExceeded。未知错误、运行中、已知等待输入/审批、人工暂停或预算限制不续接。
- 旧规则升级后不自动放宽。省略trigger时保留原条件，新API调用省略仍是quota_stop；管理页的新建/首次快捷加入默认明确预输入。每条规则都显示其条件，用户可编辑选择。重复/指定次数的显式预输入在每个新恢复周期检查当时的空闲对话，不锁定最初的回合；单次锁定选定回合。仅保存规则不发消息，不为了测试伪造额度失败。
- 最近对话快捷开关用 warmup_rule_set_enabled，必须指定目标状态及当前 expected_revision，加入时confirm_send=true。取消只停用并保留消息、次数配置，不能解释成撤回已投递消息。不得自行批量加入用户没有选定的对话。
- 页面保存按钮本身代表发送授权，不再要求额外勾选框。规则右上角滑动开关控制启停，底部下拉选择执行方式；模型调用工具仍需先获得用户明确意图，不能伪造授权。warmup_rule_set_mode只改次数，不自动启用已停用规则。
- 续聊使用官方 codex queue，不覆盖原对话模型或权限，不代答审批。后台暂停会同时暂停预热与续聊；每条规则可在管理页单独停用。
- 配置 Aion 恢复桥后，只有桥明确判定为普通对话才直接排队；唯一匹配的协作交桥恢复原关联。桥不可用、归属不明或任务过期时不回退普通“继续”。不得自行重开过期讨论、补充预算或重发原实施单；结果未知只查询原尝试回执，不重新发送。桥入口路径属于本机配置，不复制其令牌或群上下文文件。
- 正常完成回合的预输入需桥支持只读resolve_preinput，并核对threadId/completedTurnId回显；只接受ordinary/blocked/ambiguous，不使用quota恢复句柄，也不授予群共享权。旧桥不支持时保留次数、不普通回退。
- 低额度提醒是可选PostToolUse Hook，默认关闭。用户开启后可用warmup_warning_configure(enabled,threshold=3或5)配置；仍须用户亲自审阅信任Hook，不能用bypass、修改信任记录或伪装managed绕过。Hook只在工具执行后附加提示，每周期每对话至多一次；不发新回合、不阻断/改写工具、不自动保存规则。没有工具调用时不能保证及时提醒。
- 收到低额度提示不等于新增任务或授权。仅在用户已允许为当前未完成任务安排续接时保存对应预输入；需要用户决定、任务已完成、主动暂停或无合适权限时不自行续接。检查已有规则，避免重复；其他对话模型和权限保持原样。
- 续聊要求 Codex 桌面程序仍在运行；不自动启动Codex。预热本身不要求主程序运行。GUI未运行时保留规则，等程序运行且条件仍符合再检查。
- “已排队”仅表示队列接收，不代表已开始执行或完成。单次尝试后停用；超时/结果不明不自动重发，同一额度中断轮次不重复投递。
- 工具尚未加载时，可在插件目录使用 python -B server.py status/pause；不要为了刷新工具新建对话，除非用户授权。

详细边界与移除方法见 ../../README.md。
